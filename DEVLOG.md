### Thinking out loud

**Vanilla JS vs React/Next.js** — I noticed the frontend feels "hardcoded" compared to React apps. After digging into why, the core trade-off became clear:

- Vanilla JS has zero build step → Claude Code edits are instantly visible on refresh. This keeps the AI iteration loop as tight as possible.
- React/Next.js gives you declarative UI, virtual DOM diffing, and smooth partial updates — but adds a build pipeline and framework abstractions that slow down the AI-edit cycle.
- For a one-week hackathon where the AI agent is doing most of the coding, minimizing friction between "AI writes code" and "I see the result" matters more than component elegance.

**Current stance:** Vanilla JS is the right call for the hackathon. If Capis continues post-competition, Web Components (no build) or React (full ecosystem) are the two upgrade paths.

**All data is mock** — feeds, signals, portfolio are all generated by a seed script. No third-party APIs yet. This is intentional — get the UX right first, wire up live data later.
